# BJJ RollMaster

Турнирное приложение для бразильского джиу-джитсу: таймер раундов, счёт, сетки, дашборд и онлайн-регистрация атлетов с подтверждением организатором. Данные хранятся в общем бэкенде (Node.js + SQLite), доступном с нескольких устройств. Живой счёт/таймер каждого ковра синхронизируется между пультом оператора и ТВ-табло через WebSocket — можно вести несколько ковров параллельно с разных устройств.

## Запуск локально

**Требования:** Node.js 20+

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Скопировать `.env.example` в `.env` и задать `ADMIN_TOKEN` (нужен для подтверждения заявок, добавления атлетов, генерации сеток и т.д.):
   ```bash
   cp .env.example .env
   ```
3. Запустить фронтенд и бэкенд вместе:
   ```bash
   npm run dev:all
   ```
4. Открыть в браузере: http://localhost:3000
5. В разделе «Настройки» введите тот же `ADMIN_TOKEN`, что и в `.env` — без него подтверждение заявок и другие изменения будут отклоняться сервером (401).

Публичная страница саморегистрации атлетов (без панели оператора): `http://localhost:3000/?register=true` — можно раздавать участникам по ссылке/QR-коду. Заявки попадают в очередь «Заявки» и требуют подтверждения организатора, прежде чем атлет появится в сетке.

## Деплой

Один `Dockerfile` собирает фронтенд и бэкенд и раздаёт всё одним процессом (см. `render.yaml` для деплоя на Render — нужен постоянный диск под SQLite-файл и переменная окружения `ADMIN_TOKEN`, заданная вручную в панели, не в репозитории).

Для E2E в других браузерах установите браузеры Playwright:
```bash
npx playwright install
```
Затем в `playwright.config.ts` можно включить проекты `firefox` и `webkit`.

## Безопасность и аудит

- **Импорт данных:** проверка размера файла (макс. 5 МБ), валидация схемы (competitors, matches, timerConfig) — на клиенте и повторно на сервере.
- **Мутирующие эндпоинты API** защищены общим `ADMIN_TOKEN` (`Authorization: Bearer`, constant-time сравнение); чтение (ростер, сетки, конфиг таймера, нужны ТВ-табло) — публичное без токена.
- **Публичная регистрация** (`POST /api/registrations`) ограничена по частоте запросов (`express-rate-limit`) и требует подтверждения организатором, прежде чем попасть в ростер/сетки.
- **WebSocket-канал таймера (`/ws`):** состояние ковра хранится только в памяти сервера (не в БД) и валидируется на входе; переподключение с backoff на клиенте.
- **Типизация:** строгие типы для переводов и пропсов, без `any` где возможно.
- Сборка не подставляет секреты из env в клиент (удалены неиспользуемые `GEMINI_API_KEY` из Vite); `ADMIN_TOKEN` хранится только на сервере и, отдельно, в localStorage браузера организатора.

## Структура

- `App.tsx` — корневой компонент, маршрутизация по экранам, опрос бэкенда, импорт/экспорт.
- `components/` — Timer, Dashboard, TournamentManager, BracketView, PublicRegister, PendingRegistrations.
- `services/api.ts` — клиент к бэкенду (fetch-обёртка с admin-токеном).
- `services/matSocket.ts` — WebSocket-клиент живого табло (реконнект с backoff).
- `server/` — Express + SQLite + WebSocket бэкенд (`src/routes`, `src/db`, `src/ws`, `src/middleware`, `src/__tests__`).
- `types.ts` — типы и хелперы (вес, пояса).
- `translations.ts` — строки EN/RU.
- `e2e/` — E2E-тесты Playwright.
